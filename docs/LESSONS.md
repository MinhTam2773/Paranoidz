## Windows & shell

- **`supabase/.env.test.local` has CRLF line endings** (2026-10-14): `. file` in Git Bash keeps the `\r` in `TEST_DB_PASSWORD` → `db push --db-url` fails with "password authentication failed". Parse it with Node (strip `\r`, `encodeURIComponent`) instead. The file lives only in the main checkout, not in worktrees.
- **Windows: Python reading stdin (heredoc) decodes it as cp1252, not UTF-8.** Vietnamese text passed that way came out as mojibake ("Háº¿t hÃ ng") and a failed write emptied a file. Read `sys.stdin.buffer` and decode UTF-8 explicitly (Python source in a heredoc is fine — only data read from stdin is affected), and grep the diff for "Ã|áº|á»" after bulk edits.
- **curl from Git Bash on Windows sends non-ASCII JSON args mangled** (Resend test subject "Kiểm tra" arrived as "Ki?m tra"). Test-only artifact; send Vietnamese test payloads from a UTF-8 file (`-d @file.json`) or from Node.
- **Running admin `src/lib` modules with plain `node` (scratch checks, `node --test`):** Node's built-in TS stripping rejects constructor parameter properties (`constructor(readonly x)`) — write fields out; `import "server-only"` only resolves inside Next (the admin app has no `server-only` dependency; Next aliases it) — standalone scripts need a resolve hook mapping it to an empty module (`module.register`); import absolute Windows paths as `file:///C:/…`. The admin `tsconfig` targets ES2017: no `123n` BigInt literals, use `BigInt(…)` / `BigInt.asUintN`.
- **Node 24 runs `.ts` directly** (type stripping) — handy for quick helper checks — but on Windows an absolute import needs a `file:///C:/...` URL, and the file should be `.mts` to skip the module-type warning.
- **Git Bash mangles non-ASCII in `curl -d '<json>'` on Windows** (PostgREST "Empty or invalid json"). Write the payload to a file with Python (`ensure_ascii=False`) and send `--data-binary @file`.

## Supabase

- **`supabase gen types --db-url` needs Docker** (not installed). For the test project use `supabase gen types typescript --project-id mnxbymkvectnvtcplrfj --schema public` (management API), then keep the file's CRLF and prod's `PostgrestVersion`; `gen:types` (`--linked`) is prod.
- **Supabase free cap = 2 active free projects per Owner/Admin, across all their orgs** (2026-10-13). Paused projects don't count; a Developer-role member doesn't count. `supabase projects api-keys` (CLI 2.72) returns the `sb_secret_` key masked but the legacy `service_role` JWT in full. Session pooler for both projects is `aws-0-ap-southeast-1` (`aws-1` → "tenant not found"); a password with `%#?&` must be `encodeURIComponent`-ed in `--db-url`. `npx supabase` fails on the root `devEngines` (npm) — use `pnpm exec supabase`.
- **No admin user seeded.** Deliberately — a committed password on an `is_admin` account would be a real hole. The owner promotes their own account once, by hand (SQL editor or `supabase db query`, never a migration): `update public.profiles set is_admin = true where id = (select id from auth.users where email = 'tamnguyen277353@gmail.com');` Done 2026-10-01 for user `995ee159-…` (via the service role, on the owner's request).
- **The claude.ai Supabase connector is read-only.** `execute_sql` fails on any write (`cannot execute INSERT in a read-only transaction`). Use it to inspect; write data through the CLI (`supabase db push --include-seed`).
- **`db push --include-seed` never re-runs a seed file it has seen** — it only updates the hash. New seed data needs a new file in `sql_paths`.
- **`SUPABASE_SERVICE_ROLE_KEY` is in `apps/admin/.env.local`** (and the storefront's): the smoke test and every helper script read it from there, and the storefront's checkout + order lookup use `admin.ts` at runtime. Vercel needs it in both projects' env (server-only, never `NEXT_PUBLIC_`).
- **Env var is `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`**, not `..._ANON_KEY`: uses the modern `sb_publishable_` key (same `anon` role under RLS, rotates independently). ARCHITECTURE.md §2.1 still says "anon key" — same thing.
- **`@supabase/ssr` `setAll(cookies, headers)`** — the second arg carries no-cache headers that must be put on the response, or a CDN can serve one user's session cookie to another. Any new cookie adapter must forward them.
- **Column-grant denials say "permission denied for table profiles"**, not "column". Map it to a friendly message in the account page, don't match on the word "column".
- **`supabase db dump` / `db reset` need Docker Desktop running.** `migration list`, `db push` and `inspect` do not.
- **Auth redirect allow-list is dashboard-only** (Authentication → URL Configuration; prod: Site URL `https://paranoidz.vn`, `https://paranoidz.vn/**` + localhost entries). An unlisted `redirectTo` silently falls back to the Site URL and drops `?next=`. Never allow-list a domain the client doesn't own (`paranoidz.com` isn't theirs) — whoever holds it could receive login tokens via a crafted `redirect_to`. Hosted auth settings are not in git — `supabase/config.toml` is the local stack only; never `supabase config push` it blindly.
- **Password minimum is 8 in both the forms and the Supabase project** (set 2026-09-27).
- **Google let a non-test user sign in while the consent screen is in Testing (unexplained, 2026-09-27).** Only `tamnguyen277353@gmail.com` is a listed test user, yet `bimtretrau@gmail.com` signed in with Google fine (new account → phone step → `0968874402`). Expected Google to block it with "access blocked / app not verified". Not investigated: that account may have a role on the `paranoidz` Cloud project, or Google may not enforce the test-user list for non-sensitive scopes (email, profile, openid). Harmless either way; publishing the consent screen after launch makes it moot. Don't rely on the test-user list as an access control.
- **Facebook development mode refuses anyone without an app role** ("Ứng dụng không hoạt động" / "App not active" page, seen 2026-09-27 with a second Facebook account in a private window). Only the app admin (owner's Facebook) can log in until the app goes Live. To test with another Facebook account: Meta app → App roles → Roles → Testers → Add people, then that account accepts at `developers.facebook.com/requests`.
- **Supabase links logins that share a verified email into one account**: `tamnguyen277353@gmail.com` has email + Google + Facebook identities on one user, so a Google/Facebook login on an existing email account lands straight on `/account` (phone already set). Expected Supabase behaviour; nothing in our code does it.
- **Supabase auth events can arrive twice on page load** (INITIAL_SESSION + a second event for the same user). Any store keyed on the session must dedupe by user id, or its second fetch can overwrite newer local state.
- **Another local Supabase project (`supabase-demo`) auto-starts with Docker Desktop** and holds ports 54321–54324; `supabase stop --project-id supabase-demo` (data kept) before `supabase start` here.

## Next.js / React / Tailwind

- **A Next dev hot reload can leave stale-prop errors in the console** (2026-10-12): after changing a component's props, the open page re-rendered it with the old data shape (`Cannot read properties of undefined`). Reload and re-check before treating a console error as a bug.
- **`next build` can fail on a corrupted `.next/dev/types/validator.ts`** ("Cannot find name 'TCH'") left by a dev server that ran alongside a build. It's generated: stop the dev server, `rm -rf apps/<app>/.next/dev/types`, rebuild.
- **Next 16: middleware is `src/proxy.ts`**, exporting `proxy()`, Node runtime only.
- **Tailwind only sees whole class names written in source.** `` `bg-${c}` `` generates nothing. Map variants to full literal class strings.
- **Deleted routes leave stale types in `.next/dev/types`**, and `next build` then fails type-check (`Cannot find module .../zz-check/route.js`). `rm -rf apps/<app>/.next` after deleting a route.
- **Tailwind v4 moves elements with the `translate` CSS property, not `transform`.** Check `getComputedStyle(el).translate` when verifying slide-ins.
- **Off-screen elements' shadows bleed into view.** A `translate-x-full` panel with `shadow-3` paints a 32px grey strip on the right edge; apply the shadow only in the open state.
- **React Compiler lint (`react-hooks/set-state-in-effect`) rejects "reset state on pathname change" effects.** Close menus in the link's `onClick` instead.
- **`next.config.ts` reads `NEXT_PUBLIC_SUPABASE_URL` at config time** (image `remotePatterns`). Vercel must have it set for the build, not just at runtime, or `new URL()` throws.
- **Verify caching on the production server, not dev** — `next dev` never caches (`storefront-prod` config: build first, then `preview_start`). Production also prefetches visible `<Link>`s, so nav routes that don't exist yet (now only the two collection slugs) show as 404s in the console.
- **Inputs under 16px make iOS Safari zoom on focus.** Checkout, order lookup and search inputs use `text-base` (16px) below `lg` as a deliberate exception to DESIGN.md sizes.
- **Long unbroken text overflows mobile.** Any user-supplied string echoed in a flex/`items-start` layout needs `wrap-break-word` (+ `max-w-full`), or the page zooms out on phones (search's 100-char query hit 851px).
- **Next.js runs server actions one at a time per client.** A slow action (e.g. search suggestions) delays the next one, including `getCartItems` / `placeOrder`. Fine with the 250ms debounce; if suggestions ever get slow, move them to a GET route handler (parallel + CDN-cacheable).
- **React: state updates after `await` inside `startTransition` are NOT part of the transition.** With server actions that `revalidatePath`, closing a form / switching view after the await shows stale props until the refresh lands. Wrap them again: `startTransition(() => setEditing(false))`. Applies to any future "save then close" UI.
- **`dialog.close()` (or any DOM call) inside `startTransition` runs immediately** — only state updates are deferred to the transition. To keep a modal open until the revalidated page lands, clear state in the transition and close the dialog from an effect on that state (`OrderActions.tsx`).
- **Admin widths: the 240px sidebar makes viewport breakpoints misjudge the room.** At 1280px the content area is 992px; at `md` (768) it is 480px. For layouts inside cards, use container queries (`@container` + `@3xl:` etc., built into Tailwind v4) — the dashboard's latest-orders rows do.
- **A form that remounts on a data-version key loses its own state** — any message that must survive the save (notice, toast) has to live above the key (`ProductEditor`).
- **Async transitions defer the first state update.** A `setX()` that runs synchronously inside `startTransition(async …)` (before the first `await`) is a transition update and doesn't render until the whole action finishes. Progress indicators for long loops belong outside the transition (`ImageManager` upload).
- **Same-page hash links append instead of replacing in Next 16.2.10** — from `/policy#shipping`, the footer's `<Link href="/policy#returns">` gives `/policy#shipping#returns` (scroll still lands on Đổi trả; a reload of that URL doesn't). Framework behaviour, not the page; a plain `<a>` for the policy links would avoid it at the cost of a full load from other pages.
- **Smooth `scrollIntoView` + a state change that shortens the page = no scroll in Chromium** — the re-render cancels the smooth scroll. Scroll instantly (or after commit) when the same click also re-renders the list.
- **`backdrop-filter` (and `transform` / `filter`) on an ancestor turns `position: fixed` children into children of that ancestor** (2026-10-16, the mobile menu bug). Put blur on a sibling layer, never on an element that contains fixed overlays.

## Built-in browser pane & Claude in Chrome

- **The built-in browser pane blocks `window.open`** (2026-10-15) — returns `null` even inside a click, so the admin's IN PHIẾU shows its popup-blocked toast there. Check new-tab flows in Chrome.
- **Agents can't sign in through the built-in browser pane** — login sends the password to supabase.co (not a local host), and the storefront callback only takes PKCE codes. Signed-in checks (saved addresses, admin pages) need the owner to sign in in the pane or in Chrome first.
- **Claude in Chrome: the first click after switching tabs often does nothing** (2026-10-15) — click again and check with a screenshot. Once, a tab with a `<dialog>` open stopped responding (screenshots and JS timed out, renderer "frozen") — close it and use a fresh tab. The built-in pane can't screenshot or click while the Claude window is behind another window; `form_input` + `javascript_tool` still work.
- **Claude in Chrome ref clicks right after a reload can miss** (2026-10-12): a `find` ref clicked before hydration did nothing; a coordinate click after a fresh screenshot worked. Also `li.querySelector("button:last-child")` matches any button that is last in *its* parent — use `li.lastElementChild`.
- **Claude in Chrome can't shrink the window below ~662px** (2026-10-14) — `resize_window` 375 leaves `innerWidth` 662. Check 375px in the built-in browser pane (`resize_window` preset mobile) instead.
- **Browser pane can't screenshot `file://` pages.** For visual review of local images, build a contact sheet PNG with Pillow and Read it.
- **Resizing the browser pane across the 768px breakpoint animates the admin sidebar** (it slides out over 300ms), so a screenshot right after `resize_window` shows it half-off. Wait ~1s or measure `getBoundingClientRect`.
- **Next dev indicator ("N" bubble, bottom-left) covers the admin logout button** in dev only. Not in production builds.
- **Built-in browser pane can't click while the Claude window is behind others** ("not on screen and has not drawn yet"); `find` / `get_page_text` still work. Use Claude in Chrome for form flows, or bring the window forward.
- **Browser pane "mobile" preset can report a wider viewport** if content forces a min-width (mobile Chrome zooms out to fit). Check `innerWidth === 375` before trusting a mobile measurement.
- **Browser pane screenshots are unreliable after scrolling in an emulated viewport** (tiled / half-painted captures). Trust measured values (`getBoundingClientRect`, `scrollWidth`) and re-screenshot after a wait.
- **Browser pane hidden = `innerWidth` 0, lazy images never load, CSS transitions and `scrollIntoView({ behavior: "smooth" })` freeze.** Set `resize_window` before measuring; verify hover effects via `el.getAnimations()` + `.finish()` then read the computed value.
- **Hidden browser pane: `document.visibilityState === "hidden"` → IntersectionObserver never fires.** Take a `computer` screenshot to force a painted frame, then read state (verified the sticky bar this way).
- **Browser pane auto-dismisses native `confirm()`** (review / reply / photo deletes on the storefront use it), so a click there does nothing in tests. Stub `window.confirm = () => true` in the page first. Also: after `location.reload()` wait for hydration before clicking tabs via JS — an early click is lost and the panel stays `display: none` (a dialog inside it measures 0×0).
- **Browser pane `ref` clicks can land on an element's bottom edge** (y = bottom) and silently miss. For repeated form submits, `form.requestSubmit()` via `javascript_tool` goes through the real React submit handler; confirm with DB state, not just on-screen text (an old error message stays visible between submits).
- **Browser pane: `<dialog>` `close` events wait for a painted frame while the pane is hidden** (`visibilityState: "hidden"`): `dialog.close()` returns but React's `onClose` runs only after a screenshot. Also the pane's screenshots don't draw `::backdrop`; check it with `getComputedStyle(dialog, "::backdrop")`.
- **Browser pane: clicks right after `navigate` can land before hydration** and do nothing (no error). Wait ~2s or check a React-driven change before trusting a click.
- **`innerText` follows CSS `text-transform`** ("Ảnh bìa" reads as "ẢNH BÌA"); use `textContent` in browser checks.

## Testing (smoke, e2e, test data)

- **Test-order cleanup: cancelling already releases AUTO-FIRST5** (`used_count = greatest(used_count − 1, 0)` + `released_at`) — don't also decrement by hand (the `used_count >= 0` check caught it once). Check `used_count` = unreleased `voucher_uses` afterwards.
- **Smoke test case 12 assumes no other active bundle contains the 4 products it picks** (≥ ₫150.000, stock ≥ 5). Once real bundles exist, it may need its own products or to deactivate others during the run.
- **"Today" in tests is the Vietnam date.** At 09:39 on 07/10 VN the machine's date read 06/10 (UTC), so an expiry of 06/10 is correctly "đã qua". Use `vnDate()` reasoning, not the local clock, when picking test dates.
- **Rate-limit cleanup must target exact buckets.** A `bucket like 'order:%'` delete (2026-10-12) also reset real visitors' hourly counters — harmless, but delete `order:phone:<test phone>` / `order:ip:<your ip>` only.
- **The voucher race test didn't hit the atomic guard.** Both losers failed `INVALID_VOUCHER` (the winner had already committed), not `VOUCHER_EXHAUSTED` — the three HTTP calls never truly overlapped. Outcome correct; the `UPDATE ... WHERE used_count < max_uses` path itself is proven only by Postgres row-lock semantics, not by this test.
- **Test sessions without passwords:** `auth.admin.generateLink({ type: "magiclink" })` → `verifyOtp({ token_hash })` gives a real user session from the service key. Use this for any future test that needs `auth.uid()`.
- **Admin unit tests:** `pnpm --filter admin test` (`node --test`, Node 24 type stripping, no test dependency). Modules under `apps/admin/src/lib/bigseller/` import each other with `.ts` extensions (`allowImportingTsExtensions`) and no `@/` aliases so the tests can load them; keep them free of Next / Supabase imports.
- **Browser checkout / lookup tests leave `rate_limits` hits** (`order:phone:<test phone>`, `order:ip:::/64` for local `::1`, same with `lookup:`). Delete them after, or the smoke test's phone-limit check fails for the rest of that hour (it assumes `order:phone:0900000001` starts at 0).
- **`place_order()` refuses a phone's 4th pending order (`TOO_MANY_PENDING`).** Bulk test orders need several phones (0900000001–09 are the test range; cleanup by phone).
- **Smoke test phones carry state between cases** — 0900000008 is blacklisted and 0900000009 has 3 pending orders by case 17, and pool variants can run out. New cases that place orders should use their own phone (`QUOTE_PHONE` pattern) and a single unit.
- **E2E (2026-10-15):** `next start` fills `x-forwarded-for` from the socket, so locally every request comes from one IP and the 10-orders/hour limit trips mid-suite — storefront tests send a random `x-real-ip` (`e2e/fixtures/test.ts`). New storefront specs must import `test` from there, not `@playwright/test`.
- **Next 16's image optimizer refuses private IPs** (`upstream image … resolved to private ip`), so product photos never render against local Supabase (`[WebServer]` noise in e2e output). Tests must not assert on images.
- **The checkout name field allows letters only** — "Khách E2E" fails validation ("Chỉ dùng chữ cái"). Test names must have no digits.
- **A first-time account lands on `/account/phone` after login**, and `/account` redirects there until the profile has a phone.
- **Next's route announcer is a `role="alert"`** (`#__next-route-announcer__`), so a bare `getByRole("alert")` is ambiguous in tests — filter by text.
- **Local sign-ups now need the confirmation email** (2026-10-16, `enable_confirmations = true` in `supabase/config.toml`, as on prod): open Mailpit at http://127.0.0.1:54324 and click the link. Don't skip Mailpit (`-x mailpit`) when starting the stack — S11 / S12 read it.
- **E2E: don't read the DB right after a UI change you only saw on screen** — A11's reply text showed before the server action committed. Poll (`expect.poll`) the row instead.
- **The full e2e suite on the dev laptop (8 cores, 4 workers + 2 prod servers + Docker) is slow**: auth / server-action round trips passed 5 s, so `expect` waits 10 s. Running it through the agent's Bash tool once died with exit 137 — run it in the background (or a terminal) when the stack is cold.
- **CI: `next build` can fail on a Google Fonts download** (2026-10-17, run 39001392777 on docs-only `3cd939a`): Turbopack reports 35 × "Module not found: Can't resolve '@vercel/turbopack-next/internal/font/google/font'" for `[next]/internal/font/google/inter_….module.css`, then "Process from config.webServer was not able to start". It means `next/font/google` couldn't fetch Inter from fonts.googleapis.com, not a code error. Vercel built the same commit fine. Check Vercel's status on the commit, then `gh run rerun <id> --failed`.
- **CI: the local auth service can boot with Supabase's default English email templates** (explained 2026-10-17): auth fetches the templates from Kong once at boot, and on a fresh `supabase start` Kong isn't listening yet (`templatemailer_template_body_http_error … connection refused` in the auth log), so it keeps the defaults. Reproduced locally after `supabase stop` / `start`. CI now restarts the auth container after `supabase start` and fails if the error shows again; locally: `docker restart supabase_auth_Paranoidz`. S11 / S12 accept only our `/auth/confirm` links, so a fallback to the defaults fails them.

## SPX

- **SPX Track Order (1.3) on the test host** (2026-10-16): `batch_search_order` returns `status_code` as a **string** ("1001"); unknown numbers → `fail_list` 13251 "tracking no cannot be found"; cancelled shipments show 7001 "Canceled". Get AWB (1.5) is documented at max 30 per call (the test host took 101).
- **SPX test host sometimes refuses a valid ward with `-2018000` "Distribution process not found … availableLaneCodeList is empty"** (2026-10-16): PZ-2026-0044 (Hà Nội, Phường Ba Đình) failed in a bulk run, then the same order + slot succeeded from its own page, and two more Hà Nội orders succeeded together in the next bulk run. Treat it as test-host flakiness; the bulk panel shows SPX's message and the order stays Đã tiếp nhận to retry.
- **SPX test host quirks** (2026-10-15): `get_pickup_time` lists ~6 months of days; `batch_get_shipping_label` still returns a PDF for a cancelled shipment (prove a cancel by cancelling again → 13002); fees are fake (₫21). 2026-10-16: 2.1 quotes a ward that doesn't exist (₫21) — ward checking is ours (`spx_locations`); each call takes 1–2 s, so 1.10 + 2.1 in a row blew the 3 s budget.
- **SPX 2.1 fails the whole batch on an unknown voucher** (2026-10-16): top-level `ret_code 11001` "voucher_utils code X is unavailable", no `fail_list` — while a known voucher that doesn't apply is a per-row `fail_list` entry (13555). Keep the plain quote in its own call. A voucher's `min_spend` is compared with the **shipping fee**, not the order value.
- **Re-pulling SPX rates:** on `spx.vn/esf-tool`, the price request is `POST /shipment/order/open/order/batch_check_order` (`parcel_info.parcel_weight` accepts an array of weights → one fee each); provinces/wards from `GET /shipment/merchant/open/location/get_sub_location_layer_info?country=VN&location_id=<id|-1>&sub_level=1&address_version=2`. Capture one real request from the form (it has to render — keep the browser pane visible) and replay it from the page. These are SPX's internal website endpoints: fine for a one-off rate check, not for production calls.

### SPX Open API reference (docs read 2026-10-14)
